# agenttools-completion

A **universal zsh tab-completion generator + auto-installer** for `argparse` CLIs.
**Stdlib only** (no `argcomplete`, no `shtab`) — `argparse` introspection plus careful zsh
escaping.

It solves the drift problem: a hand-written `#compdef` file goes stale the instant a flag
changes. Instead, generate the completion straight from the tool's own parser — the same
parser `--help` is built from — so the completion can never disagree with the flags the tool
actually accepts.

```python
from agenttools_completion import generate_zsh, install

parser = build_parser()                   # your CLI's argparse.ArgumentParser
script = generate_zsh(parser, "mytool")   # a complete `#compdef` _mytool script
result = install("mytool", script)        # writes ~/.zsh/completions/_mytool + wires ~/.zshrc
print(result.human)                       # "✓ installed completion to … run `exec zsh`"
```

## What it generates

`generate_zsh(parser, prog)` walks the parser tree and emits a valid `#compdef <prog>`
script that introspects:

- **Subcommands** — from `add_subparsers()` → `_SubParsersAction.choices`, **recursively**,
  so nested commands (`rig stats show`, `demo config get`) complete.
- **Options** — both long (`--foo`) and short (`-f`) strings from `parser._actions`, with
  the action's `help` as the zsh description. Multiple strings for one option
  (`--verbose -v`) are emitted as a `{--verbose,-v}` group.
- **`choices=[...]`** — on options **and** on positionals → offered as a `(a b c)` value
  group so Tab cycles the allowed values.
- **Value-taking options** — an option that consumes an argument but has no `choices`
  (`--config PATH`, `--output FILE`) completes to `_files` rather than being treated as a
  bare flag. Flags (`store_true`, `count`, …) stay no-arg.
- **Subcommand help** — the subparser's `help=` (from argparse's `_ChoicesPseudoAction`),
  falling back to its `.description`, used as the `_describe` description.
- **`argparse.SUPPRESS`** help — rendered as an **empty** description, never the literal
  `==SUPPRESS==`.

Dispatch uses a state machine (`_arguments -C` + `case $state` + `case $line[1]`) so deep
command trees route to the right per-command helper function. (We switch on `$line[1]` —
the parsed positional — not `$words[1]`, so a global flag typed before the subcommand
doesn't misroute the dispatch.)

### zsh-safety

The generated file is executed by zsh, where one stray `:` or `'` in a help string turns a
valid `_arguments` spec into a syntax error. The generator therefore:

- collapses every help string to a single line (newlines / whitespace runs → one space);
- escapes `:` (the spec field separator) to `\:` and `[` to `\[` inside descriptions;
- carries descriptions in single-quoted zsh strings, rendering embedded single-quotes via
  the `'\''` idiom (inside single quotes `$`, backticks, brackets are inert, so no
  per-character escaping is needed for them);
- escapes whitespace / parens / quotes inside completion **values**.

This is pinned by a test that runs `zsh -n` on the real output (and a second that `autoload`s
the function under `compinit`). If escaping regresses, those tests go red.

### Sample output (`_demo`)

```zsh
#compdef demo
# Auto-generated by agenttools_completion — do not edit by hand.
# Regenerate with the owning tool's completion command.

_demo_greet() {
  _arguments -s \
    {-h,--help}'[show this help message and exit]' \
    '--shout[uppercase the greeting]'
  _values 'value' en fr de
}

_demo_config() {
  local curcontext="$curcontext" state line
  _arguments -C \
    {-h,--help}'[show this help message and exit]' \
    '1: :->cmds' \
    '*::arg:->args'
  case $state in
    cmds)
      local -a _subcmds=('get:print a config value' 'set:set a config value')
      _describe -t commands 'command' _subcmds
      ;;
    args)
    case $line[1] in
      get)
        _demo_config_get
        ;;
      set)
        _demo_config_set
        ;;
    esac
      ;;
  esac
}
# … _demo() top-level dispatcher, then:
_demo "$@"
```

Generate it yourself: `python -m agenttools_completion.demo_cli | zsh -n /dev/stdin && echo OK`.

## Installer

| Function | Does |
| --- | --- |
| `install(prog, script, *, comp_dir=None, zshrc=None) -> InstallResult` | write `<comp_dir>/_<prog>` (0644) and ensure the zshrc fpath+compinit snippet |
| `uninstall(prog, *, comp_dir=None, zshrc=None) -> UninstallResult` | remove the file; drop the snippet only when no managed `_*` file remains |
| `status(prog, *, comp_dir=None, zshrc=None) -> StatusResult` | report file presence + fpath wiring |

- **`comp_dir`** defaults to `~/.zsh/completions` (created if missing); the script is written
  mode `0644` as `_<prog>`.
- **zshrc snippet** — a guarded, idempotent block written between sentinel lines:

  ```zsh
  # >>> agent-tools completions >>>
  fpath=("~/.zsh/completions" $fpath)
  if (( ! $+functions[compinit] )); then
    autoload -Uz compinit && compinit
  fi
  # <<< agent-tools completions <<<
  ```

  `compinit` is **guarded** — we only autoload+run it when it isn't already defined, so we
  never force a second `compinit` for users who already call it; if their own `compinit` runs
  after this block, it picks up our `fpath` entry anyway. Either way the completion loads.
- **Idempotent** — re-running `install` rewrites the block in place (never duplicates it) and
  overwrites the file. `uninstall` is a no-op when nothing is present (never raises).
- **`uninstall`** removes `_<prog>` and strips the zshrc block **only** when `comp_dir` has no
  remaining `_*` completion files (other tools may share the `fpath` entry); otherwise the
  block stays.
- **Injectable** — `comp_dir` / `zshrc` are parameters so tests (and you) can target a temp
  location and never touch the real `~/.zshrc`.

After install, run `exec zsh` (or restart the shell) to activate.

- **comp_dir-aware** — the zshrc block records the `comp_dir` it targets. `status` reports
  `fpath_configured` only when the block points at *this* dir, and `uninstall` strips the
  block only when it targets the dir being uninstalled — so injectable / multiple comp_dirs
  never cross-contaminate.

### Result objects

`InstallResult` carries `prog`, `comp_file`, `zshrc`, `file_written`, `snippet_added`, and a
ready-to-print `human` string. `UninstallResult` mirrors it with removal-shaped names
(`file_removed`, `snippet_removed`). `StatusResult` carries `file_present`,
`fpath_configured`, a derived `installed` property (file present **and** fpath wired), and a
`human` string with `✓` / `~` / `✗` phrasing.

## Wiring into a real CLI (recommended follow-up)

This module ships the generator + installer; **wiring a `<tool> completion …` subcommand
into each real CLI is a deliberate, documented follow-up** (not done here, to avoid editing
other repos). The intended shape, per consumer:

```python
# in the consumer's argparse dispatch
comp = sub.add_parser("completion", help="manage zsh tab-completion")
comp_sub = comp.add_subparsers(dest="completion_command")
comp_sub.add_parser("install",   help="generate + install zsh completion")
comp_sub.add_parser("uninstall", help="remove zsh completion")
comp_sub.add_parser("status",    help="show completion install status")

# handlers:
from agenttools_completion import generate_zsh, install, uninstall, status
if args.completion_command == "install":
    print(install("mytool", generate_zsh(build_parser(), "mytool")).human)
elif args.completion_command == "uninstall":
    print(uninstall("mytool").human)
elif args.completion_command == "status":
    print(status("mytool").human)
```

`demo_cli.py` in this package is the always-present reference: a small argparse CLI
(subcommands, options with `choices`, a nested subparser) whose `__main__` prints the
generated `_demo`.

## Installing / importing as a consumer

The package lives under `lib/` in the umbrella repo and builds as the
`agenttools-completion` distribution:

```toml
# pyproject.toml of the consumer
[project]
dependencies = ["agenttools-completion"]
```

For local/dev installs from the umbrella checkout:

```sh
pip install -e /path/to/agent-tools/lib/agenttools_completion   # editable install
# or, ad-hoc, with uv:
uv run --with /path/to/agent-tools/lib/agenttools_completion python -c "import agenttools_completion"
```

## Why stdlib only

The ecosystem is stdlib-first by directive. `argcomplete` is a **runtime** completer — it
needs a shell hook and re-invokes your Python on every Tab; heavier and slower than a static
`#compdef`, and it doesn't emit a standalone script. `shtab` does emit static scripts but is
another dependency surface for what is, for zsh specifically, a few hundred lines of
argparse-walking + escaping we can own outright and pin with a real `zsh -n` test. Owning it
also lets the escaping be exactly as paranoid as zsh demands.
